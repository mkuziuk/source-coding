# Расширенный формат описания источника

## Зачем нужно расширение

В исходном формате символы на разных тактах независимы.
Поэтому в нём нельзя записать марковский источник.
Нельзя записать и стационарный неэргодический источник.

Расширение добавляет два новых вида описания:

- марковский источник;
- смесь источников.

Старые файлы читаются без изменений.
Исходный формат остаётся частным случаем.

## Как программа узнаёт вид описания

Программа смотрит на поля верхнего уровня:

- есть поле `mixture` - это смесь;
- есть поле `memory` - это марковский источник;
- иначе - это исходный формат.

## Грамматика

```
описание      = исходный | марковский | смесь

исходный      = { "models": модели,
                  "switches": переключатели,
                  "source": [ имя переключателя, ... ] }

марковский    = { "models": модели,
                  "memory": d,
                  "initial": { контекст: вероятность, ... },
                  "transitions": { контекст: имя модели, ... } }

смесь         = { "mixture": { имя: компонента, ... } }
компонента    = описание + поле "probability": вероятность

модели        = { имя модели: { символ: вероятность, ... }, ... }
переключатели = { имя переключателя: { имя модели: вероятность, ... }, ... }

контекст      = d символов через пробел, например "0 1"
вероятность   = строка: дробь "1/3" или десятичная запись "0.3"
d             = целое число, d >= 1
```

В любом описании можно добавить поле `"comment"` со строкой.
Программа его не читает. Оно нужно только для пояснений.

Каждое распределение должно быть непустым.
Вероятности не могут быть отрицательными.
Их сумма должна быть ровно 1.
Программа проверяет это в точной рациональной арифметике.

## Смысл описаний

### Исходный формат

Смысл не меняется.
На такте `i` берётся переключатель `source[i mod L]`.
Переключатель выбирает модель.
Модель выбирает символ.
Выборы на разных тактах независимы.

### Марковский источник

Алфавит - это все символы, которые встречаются в `models`.

Первые `d` символов выбираются вместе по распределению `initial`.

Дальше источник смотрит на последние `d` символов.
Это контекст.
По `transitions` он находит модель для этого контекста.
По модели выбирается следующий символ.

Модель должна быть задана для каждого контекста из `d` символов алфавита.
Иначе файл считается некорректным.

Если `initial` - стационарное распределение цепи, источник стационарный.

### Смесь

В начале реализации один раз выбирается компонента.
Выбор идёт по полю `probability`.
Дальше всю реализацию выдаёт только эта компонента.

Компонента - любое описание: исходное, марковское или снова смесь.

Вероятность последовательности - это сумма по компонентам:
вес компоненты, умноженный на вероятность последовательности в ней.

Период смеси - НОК периодов компонент.
У исходного формата период равен `L`.
У марковского источника период равен 1.

## Почему без смеси не обойтись

В исходном формате такты независимы.
Источник повторяется с периодом `L`.
Возьмём все такты с одинаковым остатком от деления на `L`.
На них символы независимы и одинаково распределены.
По закону больших чисел частота любого слова сходится к числу.
Это число одно и то же почти для каждой реализации.
Значит, среднее по времени совпадает со средним по ансамблю.
Такой источник эргодичен.

У неэргодического источника предел частоты зависит от реализации.
Для этого нужен случайный выбор, который влияет на все такты сразу.
Именно это делает смесь: компонента выбирается один раз.
После этого такты уже зависимы.

## Ограничения

- Символ не может содержать пробел, потому что контекст пишется через пробел.
- Если есть поле `mixture`, остальные поля верхнего уровня не используются.
- Если `initial` не стационарное, точные величины режима 2 считаются от начала цепи.
  Частотная оценка при этом сходится к стационарному распределению.

## Примеры

Все примеры на параметрах варианта: алфавит a, b, c, d (k = 4), 3 модели,
в исходном формате source длины 3, в марковском глубина памяти d = 2.

| Пример | Свойство | Что его обеспечивает |
|---|---|---|
| 1 | стационарный | все переключатели дают одно распределение символа |
| 2 | нестационарный | переключатели дают разные распределения |
| 3 | эргодический | цепь из любого контекста доходит до любого, у неё нет периода |
| 4 | неэргодический | компонента смеси выбирается один раз на всю реализацию |

### 1. Стационарный источник

```json
{
  "models": {
    "m1": {"a": "1/2", "b": "1/2"},
    "m2": {"c": "1/2", "d": "1/2"},
    "m3": {"a": "1/4", "b": "1/4", "c": "1/4", "d": "1/4"}
  },
  "switches": {
    "s1": {"m3": "1"},
    "s2": {"m1": "1/2", "m2": "1/2"},
    "s3": {"m1": "1/4", "m2": "1/4", "m3": "1/2"}
  },
  "source": ["s1", "s2", "s3"]
}
```

Все три переключателя дают одно распределение: a, b, c, d по 1/4.
Например, для s3: P(a) = 1/4 * 1/2 + 1/2 * 1/4 = 1/4.
Такты независимы и распределены одинаково.
Сдвиг во времени ничего не меняет, поэтому источник стационарный.

### 2. Нестационарный источник

Файл `tests/variant_basic.json`.

```json
{
  "models": {
    "m1": {"a": "1/2", "b": "1/4", "c": "1/8", "d": "1/8"},
    "m2": {"a": "0.1", "b": "0.2", "c": "0.3", "d": "0.4"},
    "m3": {"a": "1/4", "b": "1/4", "c": "1/4", "d": "1/4"}
  },
  "switches": {
    "s1": {"m1": "1"},
    "s2": {"m1": "1/2", "m2": "1/2"},
    "s3": {"m2": "0.3", "m3": "0.7"}
  },
  "source": ["s1", "s2", "s3"]
}
```

Распределение символа зависит от позиции в source:
P(a) = 1/2 на позиции 0, 0.3 на позиции 1, 0.205 на позиции 2.
Сдвиг на один такт меняет распределение, поэтому источник не стационарный.

### 3. Эргодический источник

Файл `tests/variant_markov.json`.

```json
{
  "models": {
    "пара_ab": {"a": "1/2", "b": "1/2"},
    "пара_cd": {"c": "1/2", "d": "1/2"},
    "равномерная": {"a": "1/4", "b": "1/4", "c": "1/4", "d": "1/4"}
  },
  "memory": 2,
  "initial": {
    "a a": "1/16", "a b": "1/16", "a c": "1/16", "a d": "1/16",
    "b a": "1/16", "b b": "1/16", "b c": "1/16", "b d": "1/16",
    "c a": "1/16", "c b": "1/16", "c c": "1/16", "c d": "1/16",
    "d a": "1/16", "d b": "1/16", "d c": "1/16", "d d": "1/16"
  },
  "transitions": {
    "a a": "пара_ab", "a b": "пара_ab", "a c": "пара_ab", "a d": "пара_ab",
    "b a": "пара_cd", "b b": "пара_cd", "b c": "пара_cd", "b d": "пара_cd",
    "c a": "равномерная", "c b": "равномерная", "c c": "равномерная", "c d": "равномерная",
    "d a": "равномерная", "d b": "равномерная", "d c": "равномерная", "d d": "равномерная"
  }
}
```

Следующий символ зависит от символа два такта назад:
после a идёт a или b, после b идёт c или d, после c и d - любой символ.

Из любого контекста можно дойти до любого другого.
Контекст `a a` может перейти сам в себя, поэтому у цепи нет периода.
Такая цепь эргодична: частоты в одной реализации сходятся к одним и тем же числам.

Источник ещё и стационарный: равномерное `initial` не меняется со временем.
P(y z) = сумма по x 1/16 * P(z | x y) = 1/16,
потому что для каждого z сумма P(z | x y) по x равна 1.
Например, для z = a: 1/2 + 0 + 1/4 + 1/4 = 1.

### 4. Стационарный неэргодический источник

```json
{
  "mixture": {
    "часто_a": {
      "probability": "1/3",
      "models": {"m": {"a": "0.7", "b": "0.1", "c": "0.1", "d": "0.1"}},
      "switches": {"s": {"m": "1"}},
      "source": ["s", "s", "s"]
    },
    "часто_b": {
      "probability": "1/3",
      "models": {"m": {"a": "0.1", "b": "0.7", "c": "0.1", "d": "0.1"}},
      "switches": {"s": {"m": "1"}},
      "source": ["s", "s", "s"]
    },
    "равномерный": {
      "probability": "1/3",
      "models": {"m": {"a": "1/4", "b": "1/4", "c": "1/4", "d": "1/4"}},
      "switches": {"s": {"m": "1"}},
      "source": ["s", "s", "s"]
    }
  }
}
```

P(a) = (0.7 + 0.1 + 1/4) / 3 = 0.35.
Но в одной реализации частота a стремится к 0.7, 0.1 или 0.25,
смотря какая компонента выбрана. К 0.35 она не стремится.
Причина - компонента выбирается один раз на всю реализацию.

Каждая компонента стационарна, поэтому и смесь стационарна.

### Исходный формат

Любой файл исходного формата подходит без изменений,
например примеры 1 и 2 или пример 2 из условия задания.

## Запуск

```
./run.sh 1.1 --seed 1 файл.json 100
./run.sh 1.1 --mode 2 --seed 1 файл.json 1000 a b
```
